# STANDARD Telegram source handoff

Production INTERNET/AUTO authoritative OPENED/UPDATED candidates use the same
eligibility, stabilization and bounded Telegram queue as LOCAL. The diagnostic
standalone tool has no notification side effects. Independent SUN and MOON
controls retain their existing behavior. Disabled bodies cannot seed inheritance;
re-enabling a genuinely new encounter uses normal eligibility.

Notification handoff matches observer epoch, uppercase ICAO and uppercase body.
Only the first newly observed direct source replacement can inherit a predecessor's
successfully enqueued notification window. It copies the existing expiry exactly
(the predecessor's T0 plus the existing 60-second grace), including equality at
the boundary. Successor predictions cannot extend it. Binding occurs before
range/toggle gates, so the first replacement consumes the opportunity even when
outside range or disabled. Inherited suppression cannot chain or be renewed by
revisiting an already observed recipient. Pending, disabled, rejected and
queue-full encounters cannot seed inheritance.

Production remote bridge instances have unique encounter namespaces. LOCAL IDs
remain unchanged. Withdrawal and actual dashboard finalization close notification
state independently of diagnostic recording; runtime source/lifecycle guards
prevent reuse of old generations. Ordinary future encounters do not inherit a
general time-based suppression window.

Telegram consumes authoritative transitions, independently of coalesced public
snapshots, bootstrap/SSE delivery, or publication failures. The existing queue
still holds at most 100 messages. ENQUEUED means queue acceptance, not successful
network delivery; the existing asynchronous transport and message format remain
unchanged. Private aggregate counters distinguish eligibility, stability,
duplicates/handoff, gates, closure and queue rejection without locations.
